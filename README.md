# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（也可用任意静态服务器托管）。

## 代码分层

- `recall.js` —— **召回判断**（纯业务逻辑，不碰 DOM / localStorage）：批次状态判定、
  停用召回、换批留痕、贴线复检恢复、流转拦截等全部规则。
- `archive.js` —— **作品存档**：localStorage 读写、旧版本数据兼容；批次沿革与召回记录只追加、不删除。
- `app.js` + `index.html` —— **页面操作**：看板、表单、批次管理、召回处理弹窗等界面交互。

## 线材批次召回追踪

- 新增作品建档时必须选择一个「合格在用」批次，并把批次号、供应商、规格快照到作品上。
- 在「线材批次与召回」面板登记批次；批次只登记不删除。
- 供应商停用某批线材（输入停用原因）后：
  - 仍在使用该批次的**未交付作品**立即停在「待复核」，保留召回前状态，看板禁止任何流转与交付；
  - **已交付作品**保留原交付结果，只标出受影响批次与停用原因备查；
  - 已换过批次的作品不再受旧批次召回影响；重复停用同一批次幂等。
- 召回处理分两步，缺一不可：
  1. 更换合格批次：记录旧批次、替换时间、复核人，作品仍停在待复核；
  2. 补做贴线检查：检查合格并记录检查人后，才恢复到召回前的流转状态。
- 旧批次记录（`batchHistory`）与召回/恢复记录（`recalls`）始终保留，可在作品详情中查看
  每件作品「为何被拦、何时恢复」。
- 看板新增「待复核」「已交付」两列，顶部「召回拦截 / 恢复」小列表汇总全部受召回影响的作品。

## 原有闭环

- 新增作品并记录胎体、纹样、线条、贴线进度、阴干日期、金粉状态、缺陷和交付日期。
- 工序看板覆盖贴线中、待阴干、上金粉、待交付、待复核、已交付。
- 今日待阴干、缺陷作品、最近交付、召回拦截四类列表。
- 可更新状态、确认交付、记录断线/翘线、查看作品详情。
- 支持筛选、交付排序、localStorage 持久化和 JSON 导出（含批次与作品）。
