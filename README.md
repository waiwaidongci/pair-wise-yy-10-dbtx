# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（需通过普通 script 加载，无需构建）。

## 已实现闭环

- 新增作品并记录胎体、纹样、线条、贴线进度、阴干日期、金粉状态、缺陷和交付日期。
- **建档时记录正在使用的线材批次**（只能选合格在用批次），作品永久保留建档批次。
- 工序看板覆盖贴线中、待阴干、上金粉、待交付、已交付，以及召回专用的「待复核」列。
- 今日待阴干、缺陷作品、召回与受影响、最近交付四类列表。
- 可更新状态、记录断线/翘线、查看作品详情。
- 支持筛选、交付排序、localStorage 持久化和 JSON 导出（含批次档案）。

## 线材批次召回追踪

- 批次面板可登记供应商停用：停用批次**只标记、不删除**，停用时间与原因永久留档。
- 停用瞬间自动判定全部作品：
  - **未交付作品**：马上停在「待复核」，状态流转按钮全部锁住，详情记下拦截原因、拦截时间和拦截前工序。
  - **已交付作品**：保留原成品结果与「已交付」状态，只追加「受影响」标记（交付瞬间批次已停用同样会标记）。
  - 判定幂等，重复触发不会产生重复事件；同一批次二次停用/再次召回会追加新事件。
- 恢复流转必须按顺序完成，每一步都有服务于记录的强校验：
  1. **更换合格批次**：记录旧批次 → 新批次、替换时间、复核人（旧批次与更换史始终保留）。
  2. **补做贴线检查**：记录复检人与检查时间，未换批不能检查。
  3. **恢复流转**：两步齐备才能回到拦截前所处工序；卡片和详情可查到每件为何被拦、何时恢复。

## 代码分层

- `recall.js`：召回判断层。纯函数，不碰 DOM 与存储——批次停用、受影响判定、拦截/换批/复检/恢复的状态流转。
- `archive.js`：作品存档层。localStorage 读写、种子数据、旧版存档迁移（旧作品自动补建档批次与召回档案字段）。
- `app.js`：页面操作层。看板/批次面板渲染、表单与按钮事件，只调用上述两层，不自带判定规则。
- `index.html`：结构与样式。
